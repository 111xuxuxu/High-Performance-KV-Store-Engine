High-Performance KV Store Engine (Linux C/C++)这是一个探索 Linux 底层高性能网络 IO 与存储引擎极致性能的自研项目。系统实现了存储后端（数据结构）与网络调度引擎（IO 模型）的解耦，支持在 Reactor (Epoll)、io_uring (Async IO) 及 NtyCo (Coroutine) 之间灵活切换。🌟 项目亮点三维 IO 模型验证：Reactor (Epoll-ET)：基于非阻塞 IO 与边缘触发模式，实现经典的单线程高并发处理。io_uring (Proactor 范式)：适配 Linux 5.10+ 内核，通过 SQ/CQ 双环缓冲区实现真正的异步 IO，规避了频繁的系统调用（Syscall）开销。NtyCo (协程)：集成轻量级协程框架，将复杂的异步回调解耦为同步编程逻辑，提升开发效率。多态存储后端：Hash Table：基于 DJB2 算法 实现，通过链地址法处理冲突，点查询（Point Query）平均时间复杂度为 $O(1)$。RB-Tree：自主实现红黑树平衡逻辑，支持有序检索及 $O(\log n)$ 复杂度的范围查询。Array：针对极小规模数据的 $O(1)$ 快速删除实现。工业级协议解析：自研类 Redis 文本协议，支持 SET/GET/DEL/MOD/EXIST 等 15 种核心指令，通过物理分词器实现低延迟解析。内存安全审计：全局封装 kvs_malloc/free，结合 Valgrind 进行百万次级别压测，确保核心引擎零内存泄漏（Zero Memory Leak）。🚀 性能基准 (Benchmark)测试环境：Ryzen 7 5000H (Zen 3) @ Ubuntu 20.04 (Kernel 5.15)存储引擎IO 模型操作总数平均 QPS延迟 (Avg Latency)Hash Tableio_uring1,000,000120,000+< 10msRB-TreeEpoll100,00085,000+< 15ms结论：在高并发小包请求场景下，io_uring 相比 Epoll 吞吐量提升约 20%。🛠️ 构建与运行依赖环境Linux Kernel 5.10+ (推荐以支持 io_uring)GCC/G++ 9.0+liburing-dev编译指令Bashmake clean
